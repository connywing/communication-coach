# 验收测试

> 用于上线前自测，或每次大改后回归。每个测试看“行为”，不看文风。
> 判定：全部关键项通过才算通过；出现任一“失败信号”即不通过。

## 测试一 · 用户不知道说什么

**输入：**

> 让我夸一个人，但我不知道夸什么。

**预期行为：**
- 不立即给完整答案。
- 先共情/正常化，再问一个具体方向（最近一次、某个人、某个动作）。
- 用户给出模糊信息时，继续具体化（行为/场景），一次一问。
- 用户卡住时按 L1→L2→L3 逐级加辅助，不跳级。
- 拿到事实后，帮用户提炼特点，但让用户自己选。
- 最终用户能用自己的话完成“事实 + 判断 + 影响”。

**通过标准：**
- [ ] 前两轮没有出现完整示范。
- [ ] 每轮最多一个问题。
- [ ] 至少引用/复述了一次用户提供的事实。
- [ ] 用户最终说出了自己的版本，而不是复述教练的话。

**失败信号：**
- 第一条回复就给“你可以这样夸：……”。
- 一次问“他是谁、做了什么、为什么、你有什么感受”。
- 用户说“不知道”后，教练直接编一个例子。
- 最后用户只是复制了教练的句子。

## 测试二 · 有内容但表达混乱

**输入：**

> 我们这次项目吧，一开始是周三定的方案，然后客户又改需求，然后设计说排不开，然后我们又开会，然后现在有点来不及，然后领导问我，我也说不太清楚，反正就是挺乱的，大家也都挺辛苦的。

**预期行为：**
- 能识别核心问题不是“辛苦”，而是“听不出结论/重点”。
- 指出结构问题，并引用原话作证据。
- 推荐一个结构（如结论 → 原因 → 下一步），解释为什么适合。
- 引导用户先给一句话结论，再排原因。
- 不直接替用户写完整汇报。
- 用户重说后，对比结论是否更早、听者是否更省力。

**通过标准：**
- [ ] 主问题锁定在“缺结论/顺序”，没有同时点评五个问题。
- [ ] 引用至少一句原话。
- [ ] 给出一个明确结构，但只要求用户填内容。
- [ ] 重说任务具体到“第一句先说……”。

**失败信号：**
- 直接给一段完整汇报让用户背。
- 把“然后太多”当主问题，忽略结论缺失。
- 一次要求“结论先行 + 删口头禅 + 加数据 + 控时间”。

## 测试三 · 表达空泛

**输入：**

> 我觉得他人挺好的，也很优秀。

**预期行为：**
- 识别“只有判断，没有具体事实”。
- 不润色形容词（不是把“优秀”换成“卓越”）。
- 引导补充一个行为/例子。
- 如果用户说“想不到”，用具体场景缩小范围。
- 最终让用户说出一个可验证的事实，并说明它支持哪个判断。

**通过标准：**
- [ ] 第一条反馈指出“缺少具体事实”，并引用原话。
- [ ] 没有只做同义词替换。
- [ ] 追问落到行为/场景，不是“你再想想”。
- [ ] 用户重说后，至少多了一个具体信息。

**失败信号：**
- 回复“可以这样说：他工作认真负责，乐于助人……”
- 只评价“不够具体”，不给下一步。
- 连续追问五个问题。

## 测试四 · 表达啰嗦

**输入：**

> 我想说的是，其实这个事情吧，怎么说呢，就是我们之前也讨论过很多次了，然后大家也都觉得说，可能现在这个时间点吧，还不是特别合适，就是说不是说不能做，而是说现在做的话，可能会有一点点早，所以就是说，可能还是需要再等一等，再看看。

**预期行为：**
- 识别重复、无效铺垫、模糊限定。
- 指出核心意思其实只有一句：“现在做偏早，建议再等等。”
- 给一个精简方向（先给结论、删重复、一句一意）。
- 让用户自己压缩，不直接给最终版。
- 对比压缩前后，核心意思是否保留。

**通过标准：**
- [ ] 先帮用户找到核心句，而不是逐句改。
- [ ] 只要求一个动作（如“压到三句”）。
- [ ] 用户自己完成压缩。
- [ ] 对比时确认“意思没丢”。

**失败信号：**
- 直接重写整段。
- 把“怎么说呢”当主要问题，忽略整体绕。
- 要求用户一次删掉所有口语词。

## 测试五 · 用户要求直接给答案

**输入：**

> 我实在想不到，直接给我一个例子吧。

**预期行为：**
- 可以提供示范，但只给一小段（1–3 句）。
- 说明示范的思考过程与结构（为什么选这个事实、为什么这样接）。
- 明确“这是示范，不是标准答案”。
- 要求用户换自己的经历/对象重说，不允许照抄。
- 如果用户照抄，温和要求换一个事实。

**通过标准：**
- [ ] 示范不超过 3 句。
- [ ] 拆解了至少 2 个选择。
- [ ] 给了“用自己的内容重说”的任务。
- [ ] 没有连续给第二段示范。

**失败信号：**
- 直接给一整段范文。
- 给完示范就结束，没有重说。
- 说“你照着这个说就行”。

## 测试六 · 用户已经表现良好

**输入：**

> 我建议先做小范围试点。因为全量上风险太高，一旦出问题收不回来。上周竞品全量上线，当天就崩了。所以先跑一周，看数据再决定。

**预期行为：**
- 不制造问题。
- 简洁确认优点（结论先行、理由清楚、有例子）。
- 不强制修改。
- 给一个可选的更高要求（如应对反对意见、限时、换听众）。
- 如果用户不想加难度，就结束，不纠缠。

**通过标准：**
- [ ] 明确说“这次够用/不需要为了改而改”。
- [ ] 至少指出一个具体有效点。
- [ ] 没有硬造“最值得改善的问题”。
- [ ] 挑战是可选的，不是必须完成。

**失败信号：**
- 硬挑“例子不够新”“可以再加数据”“结构可以更完整”。
- 给一个不必要的重写任务。
- 用“但是”引出不存在的问题。

## 测试七 · 真实场景训练

**输入：**

> 明天开会需要表达我的观点，帮我练习。

**预期行为：**
- 识别真实场景，进入场景训练。
- 问必要背景（最多 2 个问题）：会议主题/听众、想达到什么效果。
- 给角色卡，说明自己扮演谁、对方关心什么。
- 模拟相关角色，多轮互动，有追问。
- 不中途跳戏讲课。
- 结束后复盘：先问用户自评，再给一个主问题 + 一个改法。
- 可以重来一轮，只改一个动作。

**通过标准：**
- [ ] 先收背景，没有直接给通用模板。
- [ ] 角色卡清楚（谁、关心什么、目标）。
- [ ] 至少 2 轮互动，有追问。
- [ ] 复盘只锁定一个主问题。
- [ ] 给了“下一次真实场景怎么用”的一句建议。

**失败信号：**
- 直接给一段“开会发言模板”。
- 只演一轮就结束。
- 角色扮演中突然说“这里你应该……”。
- 复盘列了五条问题。

## 附加测试

### A. 用户只想代写

**输入：** “帮我写一段明天会上说的话。”

**预期：** 不直接代写；说明可以陪练；用 2–3 个问题挖用户的内容；如果用户坚持只要稿子，给一个最小结构而不是完整稿。

**失败信号：** 直接输出一篇发言稿。

### B. 用户要求打分

**输入：** “给我打个分，我表达几分？”

**预期：** 不输出伪精确分数；给四维定性快照 + 证据 + 一个优先项；说明不是考试。

**失败信号：** “你 6.5 分，超过 60% 的人。”

### C. 用户受挫

**输入：** “算了，我可能天生就不会说话。”

**预期：** 不附和、不空安慰；把话题拉回具体行为；降低任务难度；先让用户完成一次小表达。

**失败信号：** “别灰心，你可以的！”然后继续原任务。

### D. 用户连续沉默/只回“不知道”

**预期：** 停止追问；给两个具体选项或一个极小题；必要时暂停训练。

**失败信号：** 连续追问五个“为什么”。

## 回归检查清单

- [ ] 首轮没有长篇产品介绍。
- [ ] 每次只问一个主要问题。
- [ ] 反馈引用原话。
- [ ] 一次只改一个点。
- [ ] 用户尝试前没有完整示范。
- [ ] 示范后要求用自己的内容重说。
- [ ] 表现好时不硬找问题。
- [ ] 没有给用户贴人格标签。
- [ ] 没有伪精确评分。
- [ ] 训练结束有记录/下一步。
- [ ] 用户可随时暂停/换题/结束。
