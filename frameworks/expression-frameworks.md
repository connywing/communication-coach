# 表达结构库

> 结构是脚手架，不是标准答案。用结构的唯一标准：**让听的人更省力，而不是让说的人更整齐。**

## 怎么选结构

先回答三个问题，再翻下面的表：

1. **对方听完要做什么？**（做决定 / 了解情况 / 被说服 / 被安慰 / 行动）
2. **对方最关心什么？**（结论 / 风险 / 原因 / 下一步 / 我有没有被理解）
3. **我手里有什么？**（一个观点 / 一组事实 / 一段经历 / 多个原因）

三个问题答完，结构通常只剩 1–2 个候选。

| 你要做的事 | 首选结构 | 次选 |
|---|---|---|
| 回答观点题 | 结论 → 理由 → 例子 | 是什么 → 为什么 → 怎么做 |
| 夸人/评价 | 观点 → 事实 → 价值 | 事件 → 细节 → 感受 |
| 汇报进展 | 结论 → 风险 → 下一步 | 背景 → 问题 → 行动 → 结果 |
| 讲项目经过 | 背景 → 问题 → 行动 → 结果 | 事件 → 细节 → 感受 → 启发 |
| 分析问题 | 现象 → 原因 → 影响 → 方案 | 结论 → 理由 → 例子 |
| 讲故事 | 事件 → 细节 → 感受 → 启发 | 背景 → 冲突 → 转折 → 结果 |
| 解释概念 | 是什么 → 为什么重要 → 怎么做 | 观点 → 事实 → 价值 |
| 表达不同意见 | 认同 → 补充 → 不同 | 结论 → 理由 → 例子 |
| 给建议/做选择 | 选项 → 标准 → 建议 | 现象 → 原因 → 影响 → 方案 |
| 被追问/答不上来 | 确认问题 → 已知/未知 → 下一步 | — |

**不需要结构的时候：** 一两句话能答完、对方只问一个事实、结构会让语气变硬、内容本身还没想清楚。这时候“自然说清楚”比“套完整模型”重要。

---

## 结构一 · 结论 → 理由 → 例子 → 回扣

**用途：** 观点表达、回答问题、讨论、面试作答。
**不适用：** 对方还不知道背景；事情本身需要按时间讲；你还没有结论。

**骨架：**

```text
我的判断是……（结论）
主要因为……（1–2 个理由，按重要性排）
比如有一次……（一个具体例子）
所以我觉得……（回扣结论，可省略）
```

**口头示例：**

> 我觉得远程办公更适合我们组。主要是省掉了通勤，大家上午能连续做深度工作。比如上周三，我们没开会，两个人一上午把方案改完了。所以至少对我们这种项目制团队，远程是加分的。

**常见误用：**
- 理由和例子混在一起，说了三个故事没有一个理由。
- 结论太晚，前面铺了三分钟背景。
- 回扣变成重复结论，没有增加信息。
- 每个理由都想展开，结果 5 分钟还没说完。

**口语连接：** “我觉得……”“主要是因为……”“拿……来说”“所以就我来看……”

## 结构二 · 观点 → 事实 → 价值

**用途：** 夸人、评价同事、推荐一个人、表达欣赏、绩效反馈中的正向部分。
**不适用：** 纯事实汇报；对方要的是批评/改进；你举不出具体事实。

**骨架：**

```text
我觉得他……（一个具体品质/判断）
有一次……（可验证的行为或细节）
这让我们/我……（带来的影响或价值）
```

**口头示例：**

> 我觉得他挺有闭环意识的。上次开会前，他先把上个月遗留的五个问题整理成一页纸发给大家。所以那次会只开了二十分钟，没再重复翻旧账。

**常见误用：**
- 只有观点，没有事实：“他人很好，很优秀。”
- 事实和观点不匹配：说“细心”，例子却是“准时”。
- 价值拔太高：“他改变了整个团队。”——过度。
- 一次夸五个品质，每个都没有证据。

**口语连接：** “我印象最深的是……”“有一次……”“这件事的好处是……”

---

## 结构三 · 背景 → 问题 → 行动 → 结果

**用途：** 工作汇报、项目复盘、讲经过、面试讲项目。
**不适用：** 对方只问结论；问题已经众所周知；行动还没发生（那叫计划，不是复盘）。

**骨架：**

```text
当时的情况是……（背景，1–2 句）
我们遇到的问题是……（冲突/难点）
所以我们做了……（关键动作，1–3 个）
结果是……（结果 + 一个反思）
```

**口头示例：**

> 这个项目原计划两周上线。做到第五天发现第三方接口不稳定，联调一直失败。我们把非核心功能砍掉，先保证主流程，同时准备了一个降级方案。最后按时上线，主流程没受影响，但报表功能晚了一周。

**常见误用：**
- 背景讲太久，问题一句带过。
- 行动列了十条，没有主次。
- 只有结果，没有反思。
- 把“我们很努力”当行动。

**口语连接：** “当时……”“卡在……”“所以我们决定……”“最后……”

## 结构四 · 现象 → 原因 → 影响 → 方案

**用途：** 问题分析、工作讨论、提建议、复盘根因。
**不适用：** 对方只要一个快速答案；原因还没查清；你没有权限提方案。

**骨架：**

```text
现在的情况是……（可观察的现象，最好有数据）
可能的原因有……（2–3 个，分主次）
如果不处理，会……（影响，对谁、多大）
我建议先……（一个优先动作 + 理由）
```

**口头示例：**

> 最近三周，客户回复率从 30% 掉到 18%。我看了下，主要两个原因：一是我们的邮件主题太泛，二是发送时间从上午改到了下午。继续这样，季度续约会有风险。我建议先做一个小实验：把主题改成具体问题，发送时间调回上午，跑两周看数据。

**常见误用：**
- 把现象和原因混在一起：“因为大家不重视，所以回复率低。”
- 原因列了五个，没有主次。
- 影响说得很大，但没有依据。
- 方案是“加强重视”“提高效率”这类口号。

**口语连接：** “现在的现象是……”“我判断主要有两个原因……”“这意味着……”“所以第一步我建议……”

## 结构五 · 事件 → 细节 → 感受 → 启发

**用途：** 讲故事、分享经历、个人成长、社交场合的自我表达。
**不适用：** 工作汇报；对方要的是结论；事件本身没有可讲的细节。

**骨架：**

```text
有一次……（时间/场景，快速进入）
最让我印象深的是……（一个具体细节）
我当时……（感受/反应，真实一点）
后来我意识到……（启发/变化）
```

**口头示例：**

> 有一次我带新人做客户拜访。出发前他把客户过去半年的投诉记录全看了一遍，还标了三个可能被问到的问题。当时我有点意外，因为我没要求他做。后来我意识到，主动准备和被动执行，差别就在这种没人要求的地方。

**常见误用：**
- 从头讲到尾，没有取舍。
- 细节很多，但没有感受和启发。
- 感受是编的/套话：“我深受触动。”
- 启发变成大道理，和故事无关。

**口语连接：** “有一次……”“我到现在还记得……”“当时我……”“后来我才明白……”

## 结构六 · 是什么 → 为什么重要 → 怎么做

**用途：** 解释概念、给外行讲清楚、培训分享、回答“这是什么意思”。
**不适用：** 对方已经很懂；你需要说服而不是解释；概念本身有争议。

**骨架：**

```text
简单说，它是……（一句人话定义，不用术语）
它重要，是因为……（对对方的影响）
具体可以这样做……（1–3 个动作）
```

**口头示例：**

> 简单说，“闭环”就是事情交出去之后，有人负责到有结果。它重要，是因为没有闭环，别人就得反复来问进度。具体做法就三步：接任务时确认交付时间，中途主动同步一次，结束后说一声结果。

**常见误用：**
- 用术语解释术语。
- 定义很长，听完还是不知道是什么。
- 只讲“很重要”，不讲“跟我有什么关系”。
- 方法列了十条，没有优先级。

**口语连接：** “简单说……”“你可以把它理解成……”“对你来说，这意味着……”“落地就三步……”

---

## 结构七 · 认同 → 补充 → 不同

**用途：** 表达不同意见、会上提反对、给同事反馈、讨论分歧。
**不适用：** 对方明显不理性、关系已经破裂；你需要先处理情绪；涉及原则/安全问题需要直接制止。

**骨架：**

```text
我同意你说的……（真实的共同点，不要假客套）
我想补一点……（你的新增信息）
不过我在……上看法不太一样，因为……（分歧点 + 理由）
```

**口头示例：**

> 我同意你说的，先把主流程跑通最重要。我想补一点：客服那边可能没准备好，上线当天会有咨询压力。不过我在时间上看法不太一样，我觉得可以晚两天，等客服培训完再上，不然第一波体验会很差。

**常见误用：**
- 假认同：“你说得对，但是……”——对方只听到“但是”。
- 认同部分太长，分歧点被淹没。
- 只反对，不给替代方案。
- 把“不同意见”说成“你错了”。

**口语连接：** “我同意……这部分”“我想补一个信息……”“我可能会稍微谨慎一点，因为……”

---

## 结构八 · 选项 → 标准 → 建议

**用途：** 给建议、做选择、帮朋友分析、会上提方案。
**不适用：** 对方只是倾诉、不需要建议；你还没有足够信息；选项之间没有明显差异。

**骨架：**

```text
现在大概有几种选择……（2–3 个，不堆）
如果按……来衡量（标准：成本/风险/时间/关系）
我倾向……，因为……（建议 + 理由）
但如果你更在意……，那另一种也合理（条件）
```

**口头示例：**

> 现在其实就两条路：一是这周就上，先小范围试；二是等下周全部准备好再上。如果按“风险可控”来看，我倾向先小范围试，因为出了问题还能收回来。但如果你更在意一次到位的体验，那等到下周也合理。

**常见误用：**
- 选项太多，每个都展开。
- 没有标准，纯凭感觉。
- 建议说得含糊：“都可以，看你。”
- 忽略对方的约束条件。

**口语连接：** “大概有两条路……”“如果按……来看”“我倾向……”“除非你更在意……”

---

## 结构九 · 确认 → 已知/未知 → 下一步（应对追问）

**用途：** 被问到没准备的问题、信息不全、需要争取时间。
**不适用：** 你明明知道答案却绕；对方要的是明确表态。

**骨架：**

```text
你问的是……，对吗？（确认问题）
目前我确定的是……；还不确定的是……（分清已知/未知）
我会在……之前确认，然后给你答复（下一步 + 时间）
```

**口头示例：**

> 你问的是客户那边能不能接受延期一周，对吧？目前我确定的是他们下周三有个活动，时间很敏感；还不确定的是他们能不能调整。我今天下午跟他们负责人确认，明天上午给你答复。

**常见误用：**
- 没听清问题就答。
- 用“可能、应该”糊过去。
- 只说“我回头看看”，没有时间点。
- 把不确定说成确定。

**口语连接：** “你问的是……对吗”“我确认一下”“目前我知道的是……”“我今天下班前给你准信。”

## 结构的淡出

结构应该越用越少，而不是越用越熟。

- **第一阶段**：给骨架，用户填。
- **第二阶段**：只给第一个空（“第一句先说结论”）。
- **第三阶段**：用户自己选结构，你只问“为什么选这个”。
- **第四阶段**：不给结构，用户说完后复盘“你刚才其实用了什么结构”。
- **第五阶段**：根据场景自动调整，不再提结构名称。

如果用户开始机械套“第一第二第三”，反而要提醒：

> “这次不用列点，就用三句话把最重要的事说清楚。”

## 常见误区

1. **结构先行**：内容还没想清楚，先套四段式，结果是整齐的空话。
2. **结构完整强迫症**：每次都要“背景-问题-行动-结果”，两句话能说完的事也铺四段。
3. **标签代替逻辑**：有“第一第二第三”，但点与点之间没有关系。
4. **结构名称表演**：满口“金字塔”“SCQA”，听的人更累。
5. **不按听众排序**：按自己准备的顺序说，而不是对方关心的顺序。
