# 观察框架

> 内容生成的起点不是“想”，而是“看见”。用户说不具体，通常不是词汇问题，是没有可说的材料。

## 一、什么是可用的观察

一个好的观察，满足三个条件：

1. **可验证**：换一个人在场，也能看到/听到类似的东西。
2. **具体**：有动作、语言、场景、结果，不是一个形容词。
3. **与判断有关**：它能支持或反驳一个观点。

反例：

> “他很有责任心。”

这不是观察，是判断。观察应该是：

> “上周五快下班时，客户临时改需求，他留下来把影响范围列清楚，发到群里才走。”

## 二、摄像机测试

> 如果当时有一台摄像机，它能拍到什么？

| 判断/评价 | 摄像机拍不到 | 改成可观察的 |
|---|---|---|
| 他很专业 | 气质、水平 | 他回答客户问题时，先确认了三个使用场景，再给方案 |
| 团队氛围很好 | 氛围 | 开会时大家会互相接话，没人被打断；有人提反对意见，其他人会追问细节 |
| 她很贴心 | 性格 | 她知道同事下午要面试，提前把会议室和简历打印好 |
| 这个流程很乱 | 整体感受 | 同一个申请要填三次表，两个系统里的状态不一致 |
| 客户很不满意 | 情绪 | 客户在电话里三次说“你们上次也是这么说的”，最后要求换对接人 |

**练习：** 让用户把一句评价改写成“摄像机拍得到”的版本。改不出来，说明他还没有观察，只有印象。

## 三、观察的八个镜头

拿到一个场景后，不要八个都问。选 2–3 个最相关的。

| 镜头 | 问什么 | 例子 |
|---|---|---|
| 动作 | 他具体做了什么？先后顺序？ | 先记笔记，再提问，最后复述一遍 |
| 语言 | 他说了什么？用了什么词？ | “我先确认一下，你的意思是……” |
| 表情/语气 | 表情、语速、停顿有什么变化？ | 说到风险时停了两秒，语速慢下来 |
| 场景 | 什么时候、在哪、周围有谁？ | 周一早会，领导在场，时间很紧 |
| 变化 | 之前怎样，之后怎样？ | 他来了之后，周报从周五拖到周三 |
| 结果 | 这件事带来了什么？ | 会议从一小时缩到二十分钟 |
| 对比 | 和别人/平时有什么不同？ | 别人只报进度，他会主动说风险 |
| 他人反应 | 旁边的人怎么回应？ | 他说完后，两个人跟着补充了问题 |

## 四、细节采集卡

对一个事件，快速记下五格：

```text
时间/场景：
他做了什么（动作）：
他说了什么（原话/大意）：
结果/变化：
我当时的反应：
```

如果五格里有三格是空的，说明细节还不够，先别急着评价。

**注意：** 不是每个细节都要写进表达。采集时可以多，表达时只留一个最有力的。

## 五、从细节到判断

### 5.1 一个细节不够

不要用一个行为给一个人下整体结论。至少问：

- 这是一次，还是经常？
- 在其他场景也这样吗？
- 有没有相反的例子？

### 5.2 一个行为可能有多种解释

> 同事开会前整理遗留问题。

可能的解释：
- 有责任心/闭环意识；
- 怕被领导问住；
- 上次被批评过，这次提前准备；
- 习惯性焦虑，必须把所有事列清楚。

不要替用户选“最高尚”的解释。问：

> “你觉得哪个最像？为什么？”
> “有没有其他可能？”

### 5.3 判断要带边界

把“他很负责”改成：

> “至少在项目收尾这件事上，他表现出很强的闭环意识。”

带边界的判断更可信，也更不容易被反例推翻。

### 5.4 判断与证据的连接句

训练用户说清楚“为什么这个细节能说明这个判断”：

```text
我观察到……（事实）
我判断……（品质/观点）
因为……（这个事实带来的结果，或它与判断之间的逻辑）
```

例子：

> 我观察到他会前把遗留问题整理成一页纸。我判断他很有闭环意识。因为这意味着他不仅接手任务，还会主动推进到有结果，别人不用反复追。

## 六、从观察到素材

素材不是“好词好句”，是**可复用的经验单元**。

### 素材卡格式

```text
事实：发生了什么（可验证）
观察：我注意到什么（细节/模式）
判断：这说明什么
价值：为什么值得说/带来了什么影响
可用场景：夸人 / 复盘 / 面试 / 分享经验
原始表达：我当时是怎么说的
```

### 例子

```text
事实：同事在会前把上个月遗留的五个问题整理成一页纸，发给参会人。
观察：他会主动梳理信息，不等别人安排；而且会标出需要决策的点。
判断：有闭环意识，能替别人降低沟通成本。
价值：会议时间缩短，遗留问题不再反复出现。
可用场景：夸同事、绩效沟通、讲团队协作。
原始表达：“我觉得他做事比较有闭环意识，会主动把遗留问题整理清楚，这样大家沟通时效率更高。”
```

### 素材保存规则

- 只存用户自己经历/观察到的，不编。
- 一条素材只保留一个核心判断。
- 必须问用户是否保存，同意才写入 `materials.md`。
- 不追求数量；一个能用在三个场景的素材，胜过十条漂亮句子。

## 七、日常 3 分钟观察练习

不需要每天打卡。用户想练时，做其中一个：

1. **一个人的一个动作**：今天注意到谁做了一个小动作？它可能说明什么？
2. **一句原话**：今天听到哪句话让你停了一下？当时的情境是什么？
3. **一个变化**：今天有什么和平时不一样？带来了什么结果？
4. **一个反例**：今天有没有一件事，推翻了你之前的某个判断？
5. **一个画面**：用三句话描述你今天看到的一个画面，不加评价。

## 八、常见错误

| 错误 | 表现 | 纠正 |
|---|---|---|
| 把评价当事实 | “他很优秀” | 摄像机测试 |
| 以偏概全 | 一次迟到 = 不靠谱 | 问“经常吗？有反例吗？” |
| 读心 | “他就是想表现自己” | 只描述行为，不猜动机 |
| 光环效应 | 喜欢一个人，所有行为都解读成优点 | 找反例/其他解释 |
| 细节堆砌 | 说了十个细节，没有判断 | 只留一个最有力的 |
| 过度升华 | 一件小事上升到大道理 | 问“这件事具体改变了什么？” |
| 只观察别人 | 从不观察自己 | 加一个“我当时的反应” |

## 九、和表达训练的衔接

- 用户说不具体 → 用本框架找事实。
- 用户有事实但不会判断 → 用 `thinking-frameworks.md` 的人物/观点链。
- 用户有判断但不会组织 → 用 `expression-frameworks.md` 的“观点 → 事实 → 价值”。
- 用户有完整素材 → 问是否存入素材库。
