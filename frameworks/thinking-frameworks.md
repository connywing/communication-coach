# 思考框架库

> 用途：用户“想不到”时，不是给他答案，而是给他一条能自己走出来的思考路径。

## 使用原则

1. **一次只问一个问题。** 连续追问会变成审问，用户会从“想”切换到“应付”。
2. **先宽后窄。** 先问方向，再问具体；先问“哪件事”，再问“哪个细节”。
3. **问到 3–5 个问题就收。** 够形成一个判断就停，不要把所有问题问完。
4. **每个问题都要能回答。** “你为什么这么想”太抽象；“是这件事让你这么想的吗”更容易接。
5. **不诱导。** 不要把答案藏在问题里（“你是不是觉得他很负责？”）。给候选时，明确说“也可以都不是”。
6. **用户给出内容后，帮他收束。** 思考的终点不是回答完所有问题，而是形成一句自己的判断。

## 一、人物评价链

**路径：行为 → 细节 → 模式 → 特点 → 价值**

| 步骤 | 问法 | 目的 |
|---|---|---|
| 行为 | “你最先注意到他做了什么？” | 从评价回到事实 |
| 细节 | “当时具体是什么情况？他说了什么/做了什么？” | 拿到可验证信息 |
| 模式 | “这是一次，还是经常这样？” | 判断稳定性 |
| 特点 | “如果用一个词概括，你会选哪个？” | 形成判断 |
| 价值 | “这个特点给别人/团队带来了什么？” | 说明意义 |

**卡点处理：**
- 用户说“没有特别的事” → 缩小到“今天/这周/最近一次”。
- 用户说“就是感觉” → 问“哪个瞬间让你有这个感觉？”
- 用户给出多个特点 → 让他选一个最重要的，其他先放下。
- 用户选的特点和事实不匹配 → 不否定，问“这个事实更能说明 A 还是 B？”

**示例追问：**

> “不用急着评价。就说最近一次，你注意到他做了一个什么动作？”
> “这个动作和旁边的人有什么不一样？”
> “这是一次性的，还是他平时也这样？”
> “如果只选一个词，你会用哪个？”
> “这个特点给你们组带来了什么具体影响？”

## 二、观点形成链

**路径：问题 → 初步判断 → 理由 → 证据 → 反例 → 修正**

| 步骤 | 问法 | 目的 |
|---|---|---|
| 问题 | “你被问到的到底是什么？用一句话复述。” | 防止答偏 |
| 判断 | “如果只能选一个立场，你选哪个？” | 逼出观点 |
| 理由 | “最主要是因为什么？先说一个。” | 找核心依据 |
| 证据 | “有没有你亲眼见过的例子/数据？” | 让观点落地 |
| 反例 | “有没有人可能不同意？他会怎么说？” | 增加深度 |
| 修正 | “听完反例，你的观点要改吗？” | 形成更稳的判断 |

**卡点处理：**
- 用户说“都行/看情况” → “那在大多数情况下，你更倾向哪个？”
- 用户只有理由没有例子 → “不用找大例子，就说你身边的一件事。”
- 用户例子和观点无关 → “这个例子能说明的是……，你想说的是这个吗？”
- 用户被反例问倒 → 正常。“那你的观点可以缩到哪个范围还成立？”

**注意：** 不是每个观点都要走到反例。时间有限时，走到“理由 + 一个例子”就够。

## 三、经历/故事链

**路径：事件 → 过程 → 细节 → 感受 → 启发**

| 步骤 | 问法 | 目的 |
|---|---|---|
| 事件 | “什么时候、在哪、你在做什么？” | 快速定位 |
| 过程 | “最先发生什么？然后呢？” | 还原经过 |
| 细节 | “哪个瞬间你印象最深？” | 找到可讲的点 |
| 感受 | “当时你第一反应是什么？” | 增加真实感 |
| 启发 | “现在回头看，这件事让你明白了什么？” | 提炼意义 |

**卡点处理：**
- 用户说“没什么特别的” → “不用特别，就说一个让你停了一下的小瞬间。”
- 用户讲成流水账 → “如果只留一个画面，你留哪个？”
- 用户感受是套话 → “当时身体/情绪上是什么反应？愣了一下？还是有点生气？”
- 用户提炼不出启发 → “这件事之后，你哪件事做得不一样了？”

**提醒：** 经历类不一定要“升华”。有时候一个好的细节本身就够了，不要逼用户讲大道理。

## 四、问题分析链

**路径：现象 → 原因 → 影响 → 方案 → 权衡**

| 步骤 | 问法 | 目的 |
|---|---|---|
| 现象 | “你实际看到的是什么？尽量不带判断。” | 分清事实与解释 |
| 原因 | “可能的原因有哪些？先列 2–3 个。” | 打开思路 |
| 主因 | “哪个最值得先查？为什么？” | 排优先级 |
| 影响 | “不解决会怎样？对谁影响最大？” | 说明严重性 |
| 方案 | “如果只做一个动作，你先做什么？” | 落到行动 |
| 权衡 | “这个方案有什么代价/风险？” | 避免单一答案 |

**原因分类提示（用户想不出时给方向，不给答案）：**

- 人的因素：意愿、能力、信息
- 流程因素：步骤、责任、反馈
- 环境因素：资源、时间、外部变化
- 结构因素：激励、权限、协作方式

**注意：** 不要一上来问“根本原因是什么”。先让用户列几个可能，再收窄。

## 五、选择/建议链

**路径：选项 → 标准 → 权衡 → 建议 → 条件**

| 步骤 | 问法 | 目的 |
|---|---|---|
| 选项 | “大概有几种选法？” | 打开选择空间 |
| 标准 | “你最在意什么？成本、时间、风险，还是关系？” | 明确评价标准 |
| 权衡 | “每个选项在这个标准上怎么样？” | 比较 |
| 建议 | “综合看，你倾向哪个？” | 形成判断 |
| 条件 | “什么情况下你会改选另一个？” | 增加灵活性 |

**注意：** 朋友倾诉时，不要直接进入这条链。先问“你是想让我帮你分析，还是先听你说？”

## 六、分歧/不同意见链

**路径：共同点 → 分歧点 → 依据 → 对方顾虑 → 回应**

| 步骤 | 问法 | 目的 |
|---|---|---|
| 共同点 | “你们俩都同意的是什么？” | 找到对话基础 |
| 分歧点 | “具体分歧在哪一句话/哪个判断上？” | 缩小分歧 |
| 依据 | “你的依据是什么？他的依据可能是什么？” | 分清事实与判断 |
| 顾虑 | “他最担心的是什么？” | 理解对方 |
| 回应 | “你能回应他这个担心吗？还是需要调整方案？” | 形成有效表达 |

**注意：** 目标不是“说服”，而是“把分歧说清楚”。有时候训练结果是“发现对方有道理”。

## 通用思考动作

### 1. 具体化（5W1H）

When / Where / Who / What / Why / How。不要六个都问，选最缺的两个。

### 2. 向下追问（5 Whys）

连续问“为什么”，但最多 3 层。超过 3 层容易变成哲学讨论。

> “为什么延期？” → “因为联调失败。” → “为什么联调失败？” → “因为接口文档一直没定。” → “为什么没定？” → 到这里通常已经够行动了。

**警惕：** 5 Whys 容易归因到个人（“因为他不负责”）。追问时把焦点放在流程/条件上，不要变成追责。

### 3. So What（所以呢）

用户说完一个事实，问：

> “所以这对听的人意味着什么？”
> “如果这是真的，那我们应该做什么？”

逼出意义，避免“只有信息，没有观点”。

### 4. 对比

- 前后对比：以前怎样，现在怎样？
- 有无对比：做了和没做，差别在哪？
- 他人对比：别人会怎么做？为什么？
- 极端对比：如果资源翻倍/减半，会怎么选？

### 5. 换视角

- 当事人：他当时怎么想？
- 旁观者：一个不了解背景的人会看到什么？
- 反对者：最挑剔的人会怎么反驳？
- 一年后：一年后回看，这件事重要吗？

### 6. 反例检验

> “有没有哪次不是这样？”
> “什么情况下这个判断不成立？”

能说出边界，观点才稳。

### 7. 钢人化（Steelman）

让用户先替反方说一个“最强的版本”，再回应。避免打稻草人。

## 帮用户收束

问了 3–5 个问题后，不要继续问。做三件事：

1. **复述**：“我听到的是：……（事实），你觉得……（判断），因为……（理由）。对吗？”
2. **让用户补最后一句**：“如果只用一句话说，你会怎么说？”
3. **停**：不要再加一个新维度。让用户去表达。

## 不要做

- 不要一次抛出一串问题。
- 不要把问题问成选择题，替用户完成思考。
- 不要在用户刚有内容时，立刻追问更深的问题。
- 不要为了“深度”逼用户升华。
- 不要用“为什么”连续轰炸；换成“是什么让你这么想”“当时发生了什么”。
- 不要把用户的回答改写成你的观点。
