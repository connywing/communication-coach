# 进度追踪

> 记录的目的是让下一次训练更准，不是做报表。
> 只记训练必需的信息；不确定是否该记，就不记。

## 一、数据放在哪

按顺序取第一个可用位置：

1. 用户指定的目录；
2. 环境变量 `COACH_HOME`；
3. `~/.communication-coach/`；
4. 当前工作目录下 `.coach/`（沙箱/无权限时兜底）。

目录结构：

```text
<COACH_HOME>/
├── profile.md
├── sessions/
│   ├── 2025-01-08-content.md
│   └── 2025-01-10-scenario.md
└── materials.md
```

**首次保存时告诉用户：**

> 我把训练记录存在 `~/.communication-coach/`，只在这台电脑上，方便下次接着练。你随时可以让我删掉。

**写不了文件时：** 用对话内小结代替，结束时给用户一段可复制保存的记录。不要因为文件失败中断训练。

## 二、profile.md 结构

保持短，控制在 60 行内。只写“影响下一次训练”的信息。

```markdown
# 表达训练档案

## 基本信息
- 称呼：
- 语言：中文
- 偏好：喜欢直接反馈 / 需要更多鼓励 / 不想做长练习
- 数据位置：~/.communication-coach/

## 当前状态
- 阶段：内容生成 / 逻辑组织 / 语言表达 / 场景应用
- 当前重点：CG-3 缺具体事实
- 难度：初级 / 中级 / 高级
- 开始日期：
- 最近训练：

## 能力快照（定性，非分数）
- 内容：发展中 —— 有判断，事实不足
- 结构：稳定 —— 能结论先行，例子有时脱节
- 语言：发展中 —— 偏书面，句子偏长
- 场景：待观察

## 反复出现的问题
- CG-3（3 次）：举例时容易回到概括
- LE-2（2 次）：铺垫偏长

## 已掌握的方法
- 摄像机测试（能自己用）
- 结论先行（提示下可以，未稳定）

## 偏好与禁忌
- 不喜欢被连续追问
- 希望练会议场景

## 最近 3 次
- 2025-01-08 内容：夸同事；改善：多了一个事实；下次：补影响
- 2025-01-10 场景：周会汇报；改善：结论提前；下次：练风险追问
- 2025-01-12 语言：压缩；未明显改善；下次：只改第一句

## 下次建议
- 继续 CG-3，换一个不熟悉的人；如果稳定，进入 LO-1。
```

**规则：**
- 能力快照用“起步/发展中/稳定/灵活”，不写分数。
- 反复出现的问题最多列 3 条。
- 已掌握的方法最多列 5 条。
- 最近 3 次只留一行一条。
- 不写用户的隐私细节、公司名、真实人名；用“同事 A”代替。

## 三、session 记录结构

文件名：`YYYY-MM-DD-<mode>.md`，同一天多次加序号。

```markdown
# 2025-01-08 · 内容生成

- 模式：内容生成 / 夸人
- 题目：夸一个最近接触的人
- 难度：初级
- 主问题：CG-3 缺具体事实
- 辅助等级：L2
- 用时：12 分钟

## 用户自评
- 最顺：
- 最卡：
- 感受（可选）：

## 第一次表达
> 用户原话（可截断，保留关键句）

## 诊断
- 做得好的：有明确判断
- 主问题：只有判断，没有可验证行为
- 证据：“他人挺好的，也很优秀”

## 引导
- 用了什么问题/提示
- 用户提供了什么事实

## 再次表达
> 用户原话

## 对比
- 改善：多了一个具体行为 + 影响
- 未改善/新问题：结尾又回到概括
- 下次：只练“事实 + 影响”一句

## 素材
- 是否保存：否 / 是（链接到 materials.md 条目）
```

**规则：**
- 原话可截断，但要保留证据句。
- 不写教练的长篇分析；只留判断和证据。
- “辅助等级”记最高一级，用于看依赖程度。
- 用户不想被记录时，跳过 session，只在 profile 写“有一次训练，未记录”。

## 四、materials.md 结构

一条素材一个块：

```markdown
## 2025-01-08 · 闭环意识

- 事实：同事会前把五个遗留问题整理成一页纸，发给参会人。
- 观察：主动梳理，不等别人安排；标出需要决策的点。
- 判断：有闭环意识，能降低沟通成本。
- 价值：会议缩短到 20 分钟，遗留问题不再反复。
- 可用场景：夸同事 / 绩效沟通 / 团队协作分享
- 原始表达：“我觉得他做事比较有闭环意识……”
```

**规则：**
- 必须经用户同意才保存。
- 一条素材只保留一个核心判断。
- 不编造细节；用户没说清的地方留空，不补。
- 用户可随时删除单条或全部。

## 五、写入流程

每次训练结束后：

1. **写 session**：按模板，30 秒内完成，不求完整。
2. **读 profile**：确认当前重点/阶段。
3. **更新 profile**：
   - 替换“最近 3 次”（保留最新 3 条）；
   - 更新“当前重点/难度”（只有证据足够才改）；
   - 反复问题计数 +1；
   - 更新“下次建议”。
4. **问素材**：有值得保存的事实/故事时，问一句；同意才写 materials。
5. **告诉用户**：一句“记下了，下次从……继续”，不展示文件全文。

**不要：**
- 每轮对话都写文件。
- 把聊天记录整段抄进 session。
- 在 profile 里写负面人格判断。
- 未经同意保存隐私/公司信息。

## 六、更新判断的规则

### 什么时候可以改“当前重点”

- 同一问题连续出现 3 次，且影响任务；
- 或原重点已连续 2 次无提示达标；
- 或用户明确要求换方向。

一次表现好/坏，不改重点。

### 什么时候可以改“阶段”

- 达到该阶段退出标准（见 `training-path.md`）；
- 连续 2 次无提示达标；
- 用户自己能用一句话说出方法。

### 什么时候降难度

- 连续 2 次明显卡住；
- 用户说“太难/想简单点”；
- 基础动作退回。

### 不要过度拟合

- 一次 session 只说明这一次。
- 用户状态、题目熟悉度、时间压力都会影响表现。
- 至少 3 个同类数据点，才谈“趋势”。
- 记录里区分“这次没做到”和“稳定做不到”。

## 七、周复盘

每周或每两周做一次，5–8 分钟。不要变成考试。

**流程：**

1. 读最近 3–5 条 session。
2. 回答五个问题：
   - 这周主要练了什么？
   - 哪个问题出现最多？
   - 哪个瞬间有具体改善？
   - 哪个问题还没动？
   - 下周只练一个什么？
3. 输出三句话：

```markdown
**进步证据：** ……
**仍卡的点：** ……
**下周重点：** ……
```

4. 更新 profile 的“下次建议”。

**不要：**
- 输出长篇周报。
- 用训练次数当唯一成果。
- 把“没练”说成退步。
- 给用户排名/百分比。

## 八、看什么指标（定性）

不追求精确统计，但可以看六个信号：

| 信号 | 怎么看 | 说明 |
|---|---|---|
| 二次表达改善率 | 最近 10 次里，重说后有可观察改善的比例 | 改善定义见下 |
| 自主完成率 | 无 L3 以上辅助就完成的比例 | 看是否越来越独立 |
| 提示依赖 | 最近几次的最高辅助等级 | 从 L4 降到 L1 是进步 |
| 跨题迁移 | 换新题后，上个方法还能不能用 | 比单题重复更重要 |
| 训练持续性 | 每周 1–3 次即可 | 不追求每日 |
| 用户感受 | 用户自己觉得“有没有用/难不难” | 每次可问一句 |

**“改善”的判定（满足任一）：**
- 结论更早出现；
- 多了一个可验证的事实/例子；
- 删掉了明显重复；
- 直接回应了对方的问题；
- 表达更接近自然说话。

**不把“变长”当改善。**

## 九、趋势解读

- **上升**：同类任务连续 3 次改善，且提示减少 → 可以升级。
- **平台**：连续 3–4 次无变化，但用户不挫败 → 换题型/缩小任务，不换能力。
- **波动**：时好时坏 → 正常；看是否与题目熟悉度/状态相关，不急着定性。
- **回落**：原本稳定的动作又消失 → 降难度，回到基础动作练 1–2 次。
- **假进步**：只有提示下能做到 → 不算掌握；下次换新题验证。

## 十、隐私与删除

- 只存训练必需内容；不存公司机密、真实姓名、联系方式。
- 首次保存时说明位置和用途。
- 用户说“删掉记录”：确认范围（单条/全部），删除对应文件，并在 profile 里清空。
- 用户不想被记录：尊重，只用对话内小结。
- 不把记录用于训练之外的用途。

## 十一、对话内兜底格式

不能写文件时，每次结束给：

```markdown
**训练记录（可自行保存）**
- 日期：
- 题目：
- 主问题：
- 第一次：
- 这次做到的：
- 下次：
```

只保留关键句，不复制全文。
